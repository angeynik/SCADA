# OPC UA

Сервер OPC UA (`opcua/`, библиотека node-opcua) показывает внешним клиентам модель здания и текущие значения тегов: UaExpert, сторонней SCADA, системе учёта. Свой интерфейс (`../client`) работает не через OPC UA, а через WebSocket-шлюз (этап 8).

> Этап 4 — только чтение. Запись из OPC UA появится на этапе 5 вместе с `commandGateway`, а вход по имени и паролю — вместе с пользователями (`userStore`). До этого в рабочем режиме войти нельзя никому, для проверки клиентом используется режим разработки (`OPCUA_ALLOW_INSECURE=true`).

## Настройки (conf.env)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `OPCUA_ENABLED` | `true` | `false` — сервер OPC UA не запускается |
| `OPCUA_PORT` | `4840` | Порт TCP |
| `OPCUA_INTERFACE` | `0.0.0.0` | Адрес интерфейса для привязки. На сервере с двумя сетями — адрес в сети клиентов, а не контроллеров |
| `OPCUA_HOSTNAME` | имя машины | Имя или IP в адресе точки входа (`opc.tcp://<имя>:4840`) и в сертификате сервера. Клиенты должны находить сервер по этому имени |
| `OPCUA_NAMESPACE_URI` | `urn:scada-bms:model` | URI пространства имён модели. Индекс пространства клиент берёт из `NamespaceArray`: он может отличаться между серверами, URI — нет |
| `OPCUA_ALLOW_INSECURE` | `false` | `true` — разрешены режим None и анонимный вход. **Только для разработки**, сервер пишет предупреждение в лог ошибок |
| `OPCUA_MAX_SESSIONS` | `20` | Наибольшее число сессий и подключений (1–500) |
| `PKI_DIR` | `pki` | Каталог сертификатов (относительный путь — от каталога сервера). В git не попадает |

## Модель в OPC UA

```
Objects
└── B1                          папка объекта (s=B1), описание — title из site.json
    ├── AHU-01                  установка, Object типа AhuType (s=B1/AHU-01)
    │   ├── SupplyTemp          тег (s=B1/AHU-01/SupplyTemp), BaseAnalogType
    │   │   └── EngineeringUnits
    │   ├── SupplyTempSp        BaseAnalogType + EngineeringUnits, EURange (10…30)
    │   ├── Season              MultiStateValueDiscreteType: EnumValues, ValueAsText
    │   └── Command             Boolean
    └── AHU-17
Types/ObjectTypes/BaseObjectType
└── AhuType                     тип из шаблона (s=type:AhuType), параметры — Optional
```

- **NodeId строковые и равны идентификатору тега**: `ns=<индекс>;s=B1/AHU-17/SupplyTemp`. Они не меняются при перезапуске, добавлении установок и переводе установки с N30 на ОВЕН. Клиенту достаточно один раз настроить подписку.
- **Тип установки** — ObjectType из шаблона, его NodeId — `s=type:<шаблон>`. Все параметры в типе с правилом `Optional`: экземпляр может исключить параметр (`exclude`), и такого узла у него нет.
- **DisplayName** — имя параметра (`SupplyTemp`), **Description** — заголовок параметра из шаблона («Температура приточного воздуха») или название установки.
- **Вид переменной:**

| Параметр | Тип переменной OPC UA | Свойства |
|---|---|---|
| Целочисленный с `states` | `MultiStateValueDiscreteType` | `EnumValues` (тексты состояний), `ValueAsText` (текст текущего) |
| Числовой | `BaseAnalogType` | `EngineeringUnits`, если задан `unit`; `EURange`, если заданы `min` и `max` (с учётом переопределения в экземпляре) |
| `Boolean`, `String` | `BaseDataVariableType` | — |

- **Единицы измерения** — `EUInformation` с кодом UNECE: `°C` → CEL, `%` → P1, `ч` → HUR, `Па`, `кПа`, `бар`, `м³/ч`, `Вт`, `кВт`, `кВт·ч`, `Гц`, `об/мин`, `В`, `А`, `м/с`, `мин`, `с`, `ppm`. Другой текст единицы передаётся как есть с `unitId = -1`. Таблица — `opcua/nodes.js`.
- Все переменные на этапе 4 **только для чтения** (`AccessLevel = CurrentRead`), запись отвечает `BadNotWritable`.

## Значения и качество

Значение и качество переменной — те же, что в `tagStore`. Каждое опубликованное изменение (с учётом мёртвой зоны тега) сразу попадает в переменную. Клиент с `samplingInterval = 0` получает изменения по событию, а не опросом.

| Качество / код | StatusCode |
|---|---|
| `good` | `Good` |
| `bad` / `NOT_CONNECTED` | `BadNotConnected` (значение ещё не получено) |
| `bad` / `COMM_ERROR` | `BadCommunicationError` |
| `bad` / `CONFIG_ERROR` | `BadConfigurationError` |
| `bad` / `BAD_VALUE` | `BadTypeMismatch` |
| `bad` / `DEVICE_FAULT` | `BadDeviceFailure` |
| `uncertain` / `STALE` | `UncertainLastUsableValue` |
| `uncertain` / `OUT_OF_SERVICE` | `UncertainSubstituteValue` |

При потере связи последнее значение остаётся в переменной, но со StatusCode `Bad…`: клиент не примет его за текущее. `SourceTimestamp` — время значения у источника, `ServerTimestamp` — время записи в переменную.

## Безопасность

| | Рабочий режим | `OPCUA_ALLOW_INSECURE=true` |
|---|---|---|
| Режимы | `Sign`, `SignAndEncrypt` | + `None` |
| Политики | `Basic256Sha256`, `Aes128_Sha256_RsaOaep`, `Aes256_Sha256_RsaPss` | + `None` |
| Вход | имя и пароль | + анонимный |

Сервер не объявляет устаревшие политики (`Basic128Rsa15`, `Basic256`) и вход по сертификату пользователя.

**Пользователи** проверяются через `authenticate(username, password)` из `userStore` (этап 5). Пока пользователей нет, вход по имени и паролю отклоняется, в лог — одна строка.

### Сертификаты

```
pki/
├── own/certs/certificate.pem   сертификат сервера (создаётся при первом запуске, самоподписанный)
├── own/private/                закрытый ключ — секрет, копировать только в резервную копию
├── trusted/certs/              доверенные клиенты
├── rejected/                   отклонённые клиенты (ждут решения администратора)
└── issuers/                    сертификаты и списки отзыва УЦ, если клиенты выпущены УЦ
```

**Новый клиент.** При первом подключении клиента в режиме Sign/SignAndEncrypt сервер не допускает его: сертификат клиента попадает в `rejected`, в лог пишется строка с именем и отпечатком:

```
[OpcUa] - certificate - клиент не допущен (BadCertificateUntrusted): UaExpert@ws-12 [5f655bba…]. Доверие: node tools/opcuaPki.js trust
```

Администратор сверяет отпечаток с тем, что показывает клиент (в UaExpert — Settings → Manage Certificates), и доверяет сертификат:

```bash
node tools/opcuaPki.js list                 # свой сертификат, доверенные, отклонённые с отпечатками
node tools/opcuaPki.js trust 5f655bba       # rejected → trusted (достаточно начала отпечатка, от 6 знаков)
node tools/opcuaPki.js untrust 5f655bba     # отозвать доверие: trusted → rejected
```

Сервер следит за каталогами, перезапуск не нужен: клиент подключается со следующей попытки.

**Клиенту** нужно доверять сертификату сервера (`pki/own/certs/certificate.pem`). UaExpert при первом подключении показывает сертификат и предлагает доверять ему. Если поменять `OPCUA_HOSTNAME`, сертификат сервера не перевыпускается сам: удалите `pki/own` и перезапустите сервер, после чего клиенты должны снова доверять новому сертификату.

## Как проверить в UaExpert

1. В `conf.env` на время проверки — `OPCUA_ALLOW_INSECURE=true` (до этапа 5 иначе не войти).
2. UaExpert → Add Server → Custom Discovery → `opc.tcp://<OPCUA_HOSTNAME>:4840`. Выбрать точку входа: `None` или `SignAndEncrypt — Basic256Sha256`.
3. Для `SignAndEncrypt`: первое подключение отклоняется. Выполнить `node tools/opcuaPki.js list`, сверить отпечаток, `trust <отпечаток>`, подключиться снова.
4. Objects → `B1` → установка → перетащить параметры в Data Access View. Качество видно в колонке Status Code.
5. После проверки вернуть `OPCUA_ALLOW_INSECURE=false`.

## Диагностика и лог

| Сообщение | Что значит |
|---|---|
| `[OpcUa] - start - opc.tcp://…; режимы …; типов N, установок N, переменных N, ns=2 (…)` | Сервер запущен |
| `ВНИМАНИЕ: OPCUA_ALLOW_INSECURE=true …` (лог ошибок) | Включён режим разработки |
| `клиент не допущен (BadCertificateUntrusted): …` | Новый клиент, см. «Сертификаты». Пишется один раз на сертификат |
| `вход … отклонён: пользователей пока нет` | До этапа 5 в рабочем режиме вход невозможен |
| `неверное имя или пароль: <имя>` | Клиент ввёл неверный пароль |
| `ошибка запуска opcua: порт TCP 4840 занят (OPCUA_PORT)` | Порт занят другим процессом; сервер не запускается (код выхода 1) |
| `[OpcUa] - node-opcua - <файл>: …` | Собственные сообщения библиотеки: предупреждения — на уровне `dev`, ошибки — в лог ошибок |

Открытие и закрытие сессий клиентов пишутся на уровне `dev`.

## Ограничения этапа 4

- Только чтение; запись, методы пуск/стоп и вход по паролю — этап 5.
- Нет Alarms & Conditions (этап 7) и Historical Access (этап 6).
- Нет резервирования (`ServerUriArray`, `ServiceLevel`) — этап 9.
- Сервер не регистрируется в LDS и не объявляет себя по mDNS: клиенту нужен адрес точки входа.

## Нагрузка

Проверено на 80 установках × 20 параметров (1 600 переменных): значения всех тегов меняются раз в секунду, один клиент подписан на все переменные (`samplingInterval = 0`, публикация 500 мс). Около 1 500 уведомлений в секунду. Процесс сервера с генератором значений занимает около 7% одного ядра и около 280 МБ памяти; бо́льшая часть памяти — стандартное адресное пространство OPC UA в node-opcua. Запуск OPC UA — около 2 с, остановка — меньше 0,1 с.
