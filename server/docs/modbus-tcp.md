# Modbus TCP (контроллеры ОВЕН)

Драйвер `drivers/modbusTcp/` опрашивает контроллеры по Modbus TCP и пишет в них команды и уставки. Привязка точек — в картах и экземплярах ([model.md](model.md)).

## Настройки (conf.env)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `MODBUS_ENABLED` | `true` | `false` — опрос выключен, теги Modbus остаются `bad` / `NOT_CONNECTED` |
| `MODBUS_POLL_MS` | `1000` | Период опроса контроллера, мс (100–60 000) |
| `MODBUS_TIMEOUT_MS` | `1000` | Ожидание ответа на запрос, мс (100–30 000) |
| `MODBUS_CONNECT_TIMEOUT_MS` | `3000` | Ожидание TCP-подключения, мс (100–60 000) |
| `MODBUS_FAIL_LIMIT` | `3` | Неудач подряд, после которых связь считается потерянной (1–20) |
| `MODBUS_MAX_GAP` | `4` | Наибольший разрыв между точками в одном запросе, регистров (0–100) |
| `RECONNECT_MAX_MS` | `30000` | Наибольшая пауза переподключения, мс (общая для драйверов) |

## Как идёт опрос

- **Один контроллер — одно соединение и одна очередь.** Контроллер определяется по `host:port`. Несколько установок на одном контроллере (разные `unitId` или адреса) обслуживаются одним соединением. Запросы к контроллеру идут строго по одному.
- **Точки объединяются в блоки.** Один запрос на блок: подряд идущие адреса одной области и одного `unitId`, разрыв не больше `MODBUS_MAX_GAP`, длина не больше 125 регистров или 2000 битов. Биты одного регистра читаются одним словом. Пример карты ОВЕН из `config/example` — 20 точек, 6 запросов за цикл.
- **Цикл.** Цикл запускается раз в `MODBUS_POLL_MS` от начала предыдущего. Если цикл длиннее, следующий начинается сразу.
- **Масштаб и тип.** Масштаб (`scale`, `offset`) и тип точки применяет драйвер, в `tagStore` попадает значение в единицах параметра. `float32` округляется до 7 значащих цифр (21.1, а не 21.100000381).
- **Порядок байт** (`byteOrder` карты или экземпляра) — в каком порядке приходят байты значения A B C D (A — старший):

  | byteOrder | Регистр 1 | Регистр 2 | Когда |
  |---|---|---|---|
  | `ABCD` | A B | C D | Стандарт Modbus |
  | `CDAB` | C D | A B | Слова переставлены — частый случай для float у ПЛК |
  | `BADC` | B A | D C | Байты в словах переставлены (влияет и на 16-битные значения и биты) |
  | `DCBA` | D C | B A | Всё наоборот |

  Если температура читается как 1.4e-41 или −2.3e+12, почти всегда виноват порядок слов. Проверка — `tools/modbusDiag.js` (ниже).

## Потеря связи и ошибки

| Событие | Что происходит |
|---|---|
| Таймаут или ошибка запроса | Считается неудача. Пока их меньше `MODBUS_FAIL_LIMIT` подряд, качество тегов не меняется: один потерянный ответ не даёт «мигания» |
| `MODBUS_FAIL_LIMIT` неудач подряд, отказ подключения, разрыв соединения контроллером | Все теги контроллера — `bad` / `COMM_ERROR`, последнее значение сохраняется. Соединение закрывается. Переподключение — через 1 с, пауза удваивается до `RECONNECT_MAX_MS` |
| Контроллер принимает соединение, но не отвечает | Связь не считается восстановленной, пока не прочитан хотя бы один блок. Пауза продолжает расти, лог не «мигает» |
| Исключение Modbus на блок (например, 2 — недопустимый адрес) | Связь есть. Блок разбивается на запросы по одной точке, чтобы найти неверную |
| Исключение Modbus на одну точку | Точка — `bad` / `CONFIG_ERROR`, ошибка в логе один раз. Остальные точки работают. Если программу контроллера исправили, точка заработает без перезапуска |

**Лог.** Потеря связи — одна строка `[ERROR]`, восстановление — одна строка info. Первое подключение после запуска пишется только на уровне `dev`, чтобы 80 контроллеров не давали 80 строк.

## Запись

`write(tagId, value)` → `{ ok: true, value }` или `{ ok: false, code, message }`. На этапе 5 запись будет выполняться только через `commandGateway` (права, диапазон, журнал).

- Запись встаёт в очередь контроллера **раньше** очередных чтений.
- `coil` — функция 5. Регистр — функция 6. Два регистра (32 бита) — функция 16.
- Бит регистра — чтение-изменение-запись: остальные биты сохраняются. Если программа контроллера меняет другие биты того же регистра в тот же момент, это изменение может быть потеряно. Команды лучше держать в отдельных регистрах или coil.
- **Подтверждение.** После записи точка читается заново, и в `tagStore` и ответ попадает то, что реально в контроллере. Если контроллер ограничил значение, клиент увидит ограниченное.

| code | Когда |
|---|---|
| `NOT_CONNECTED` | Нет соединения с контроллером |
| `OUT_OF_RANGE` | Значение не того типа или не помещается в точку с учётом масштаба (например, `int16` × 0.1 — от −3276.8 до 3276.7) |
| `WRITE_FAILED` | Контроллер отверг запись (исключение Modbus) или не ответил |
| `NOT_FOUND` | Тег не обслуживается драйвером |

## Инструменты

**Эмулятор контроллеров** — N контроллеров по одной карте на `127.0.0.1`. Значения меняются раз в секунду, записи клиента сохраняются.

```bash
node tools/modbusEmulator.js --map owen-ahu-v1 --count 80 --base-port 15020 \
     --write-instances data/config/instances/emu.json
npm start      # в другом терминале: сервер опрашивает 80 эмуляторов
```

**Диагностика установки** — каждая точка отдельным запросом: сырые слова, значение или ошибка. `--host` и `--port` заменяют адрес из конфигурации.

```bash
node tools/modbusDiag.js --instance AHU-01
node tools/modbusDiag.js --instance AHU-01 --host 127.0.0.1 --port 15020
```

```
SupplyTemp           holding:100 float32    0x999a 0x4199  19.2 °C
HeaterValve          holding:120 int16      0x0186         39 %
SupplyFanRunning     holding:12.4 bool      0x0030         true
```

**Сырое чтение** — когда карты ещё нет:

```bash
node tools/modbusDiag.js --host 10.10.1.11 --unit 1 --area holding --address 100 --count 10
```

## Нагрузка

Проверено на эмуляторе: 80 контроллеров, 1 600 тегов, опрос раз в 1 с — около 11% одного ядра и 81 МБ памяти.
