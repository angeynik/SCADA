# BACnet/IP (Metasys N30)

Драйвер `drivers/bacnetIp/` читает и пишет объекты устройств BACnet/IP: подписка на изменения (COV), где устройство её принимает, и опрос там, где нет. Привязка точек — в картах и экземплярах ([model.md](model.md)).

> Драйвер проверен на эмуляторе (`tools/lib/bacnetDevice.js`). Пилот на реальном N30 (этап 3а плана) ещё не проведён: лимиты N30 по COV, размеру запросов и поведению при ошибках нужно подтвердить на объекте, см. «Что проверить на N30».

## Настройки (conf.env)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `BACNET_ENABLED` | `true` | `false` — драйвер выключен, теги BACnet остаются `bad` / `NOT_CONNECTED` |
| `BACNET_PORT` | `47808` | Локальный порт UDP. Устройства шлют широковещательные I-Am на 47808, поэтому для поиска устройств нужен именно он. На порту может слушать только один процесс |
| `BACNET_INTERFACE` | `0.0.0.0` | Адрес интерфейса для привязки. На сервере с несколькими сетями — адрес в сети N30 |
| `BACNET_BROADCAST_ADDRESS` | `255.255.255.255` | Широковещательный адрес для Who-Is, например `10.10.0.255`. Можно с портом |
| `BACNET_APDU_TIMEOUT_MS` | `3000` | Ожидание ответа устройства, мс (200–30 000) |
| `BACNET_POLL_MS` | `2000` | Период опроса объектов без COV и проверки связи, мс (200–600 000) |
| `BACNET_FAIL_LIMIT` | `3` | Запросов без ответа подряд, после которых связь считается потерянной (1–20) |
| `BACNET_COV` | `true` | `false` — подписки не оформляются, всё опрашивается |
| `BACNET_COV_LIFETIME_S` | `300` | Срок подписки COV, с (60–28 800). Продление — на половине срока |
| `BACNET_WRITE_PRIORITY` | `8` | Приоритет записи по умолчанию (8–16). Точка может задать свой (`priority`) |
| `BACNET_MAX_OBJECTS` | `20` | Наибольшее число объектов в одном запросе ReadPropertyMultiple (1–100) |
| `RECONNECT_MAX_MS` | `30000` | Наибольшая пауза повторного опознания и поиска, мс (общая для драйверов) |

## Как идёт обмен

- **Один сокет на сервер, одна очередь на устройство.** Теги группируются по номеру устройства (`source.device`). Несколько установок на одном N30 обслуживаются одной очередью. Запросы к одному устройству идут строго по одному, запись — раньше очередных чтений. Всего одновременно — не больше 64 запросов (номер запроса BACnet один на сокет, 0–255).
- **Адрес.** Задан в экземпляре (`address`) — используется он. Не задан — драйвер ищет устройство по номеру (Who-Is → I-Am) с паузой от 1 с до `RECONNECT_MAX_MS`. Если найденное устройство потом пропало, поиск возобновляется: N30 мог получить другой адрес.
- **Опознание.** Перед опросом драйвер читает объект `device` по номеру из конфигурации: так он убеждается, что по адресу то самое устройство, и узнаёт `maxApduLengthAccepted`. Если по адресу другое устройство — теги `bad` / `CONFIG_ERROR` и ошибка в логе.
- **Опрос.** Каждый объект читается двумя свойствами: `presentValue` и `statusFlags`. Объекты собираются в запросы ReadPropertyMultiple так, чтобы ответ поместился в `maxApdu` устройства без сегментации (при 480 байтах — до 19 объектов), но не больше `BACNET_MAX_OBJECTS`.
- **COV.** Прочитанный объект подписывается (SubscribeCOV, неподтверждаемые уведомления, срок `BACNET_COV_LIFETIME_S`) и уходит из опроса. Подписка продлевается на половине срока. По стандарту устройство в ответ на подписку и продление присылает текущее значение, поэтому даже потерянное уведомление (UDP) исправится не позже чем через половину срока. Если все объекты на COV, драйвер каждые `BACNET_POLL_MS` читает одно свойство объекта `device` — так потеря связи обнаруживается так же быстро, как при опросе.
- **Подписка отвергнута** (N30 не поддерживает COV для типа объекта или кончились места для подписок) — объект остаётся в опросе. В лог — одна строка на устройство.
- **Остановка.** Сервер снимает свои подписки (не дольше 1 с на устройство), чтобы не занимать места подписок N30 до истечения срока.

## Значения и качество

| Тип объекта | presentValue | Значение параметра |
|---|---|---|
| `analog*` | REAL | Число × `scale` + `offset`. REAL округляется до 7 значащих цифр. Для целых параметров (`Int16` … `UInt32`) — до целого |
| `binary*` | ENUMERATED 0/1 | `false` / `true` |
| `multiState*` | UNSIGNED, **с 1** | Номер состояния × `scale` + `offset` |
| `characterstringValue` | CHARACTER_STRING | Строка |

**Состояния multiState в BACnet нумеруются с 1.** Если в шаблоне состояния с 0 (`"states": { "0": "Авто", "1": "Зима", … }`, так обычно в ОВЕН), у точки BACnet задаётся `"offset": -1`. Тогда «Авто» — это и 0 в теге, и 1 на N30, а после перевода установки на ОВЕН тег, архив и экраны не меняются.

| statusFlags | Качество |
|---|---|
| `fault` | `bad` / `DEVICE_FAULT`, значение публикуется |
| `outOfService` | `uncertain` / `OUT_OF_SERVICE`: значение задано вручную на N30, а не измерено |
| `inAlarm`, `overridden` или ничего | `good` |

## Потеря связи и ошибки

| Событие | Что происходит |
|---|---|
| Нет ответа | Неудача. Пока их меньше `BACNET_FAIL_LIMIT` подряд, качество не меняется |
| `BACNET_FAIL_LIMIT` неудач подряд | Все теги устройства — `bad` / `COMM_ERROR`, последнее значение сохраняется. Подписки считаются потерянными. Повторное опознание с паузой от 1 с до `RECONNECT_MAX_MS`. После восстановления — полный опрос и новые подписки |
| Устройство без адреса не нашлось | После `BACNET_FAIL_LIMIT` циклов — `bad` / `COMM_ERROR`, поиск продолжается |
| Ошибка BACnet по объекту (`unknown_object` и т. п.) | Теги объекта — `bad` / `CONFIG_ERROR`, ошибка в логе один раз. Объект опрашивается отдельным запросом и заработает без перезапуска, если программу N30 исправили |
| Ошибка на весь запрос из нескольких объектов | Запрос делится пополам, пока неверный объект не останется один |
| Abort «ответ не помещается» (`segmentation_not_supported`, `buffer_overflow`, `apdu_too_long`) | Запрос делится пополам, предел объектов в запросе для устройства уменьшается (строка в логе) |
| Значение неожиданного типа | Тег — `bad` / `BAD_VALUE`, лог один раз |

**Лог.** Потеря связи — одна строка `[ERROR]`, восстановление — одна строка info. Первое подключение пишется только на уровне `dev`.

## Запись

`write(tagId, value)` → `{ ok: true, value }` или `{ ok: false, code, message }`; `release(tagId)` — снятие команды. На этапе 5 запись будет выполняться только через `commandGateway` (права, диапазон, журнал).

- Пишется `presentValue` с приоритетом точки (`priority`) или `BACNET_WRITE_PRIORITY`. **Приоритеты 1–7 сервер не использует никогда**: это защита жизни и оборудования. Загрузчик, настройки и драйвер отвергают их независимо.
- **Снятие команды** — запись `NULL` в тот же приоритет. После этого N30 возвращается к значению с меньшим приоритетом или к `relinquishDefault`: управление снова у программы N30.
- **Подтверждение.** После записи объект читается заново. В ответ и `tagStore` попадает то, что реально на устройстве. Если более высокий приоритет (например, 5 у противопожарной автоматики) уже занят, запись примется, но значение не изменится — клиент увидит настоящее.

| code | Когда |
|---|---|
| `NOT_CONNECTED` | Нет связи с устройством |
| `OUT_OF_RANGE` | Значение не того типа (не `true`/`false` для binary, не целое ≥ 1 после пересчёта для multiState, не число для analog) |
| `WRITE_FAILED` | Устройство отвергло запись (`write_access_denied`, `value_out_of_range` …) или не ответило |
| `NOT_FOUND` | Тег не обслуживается драйвером |

## Инструменты

**Эмулятор устройств** — N устройств по шаблону на `127.0.0.1`, порты и номера подряд. Объекты создаются по параметрам шаблона, значения меняются раз в секунду, поддерживаются приоритеты и COV.

```bash
node tools/bacnetEmulator.js --template AhuType --count 80 --base-port 47900 \
     --write-instances data/config/instances/bemu.json
BACNET_PORT=47899 BACNET_INTERFACE=127.0.0.1 npm start   # в другом терминале
```

`--max-objects 5` — устройство без сегментации, отвергающее большие запросы; `--no-cov` — устройство без COV.

**Поиск устройств** (`--local-port` по умолчанию 47808: если на машине работает сервер, искать с другой машины или после его остановки):

```bash
node tools/bacnetDiscover.js --broadcast 10.10.0.255
```

Пример вывода (номера и имена условные):

```
Ответили устройств: 2

30001     10.10.0.30             maxApdu 1476  vendor 5    N30-1 · Johnson Controls · N30
30002     10.10.0.31             maxApdu 1476  vendor 5    N30-2 · Johnson Controls · N30
```

**Объекты устройства и черновик привязок:**

```bash
node tools/bacnetDiscover.js --device 30001 --address 10.10.0.30 --csv ahu17.csv --id AHU-17 --template AhuType
```

```

BO:1701    AHU17.SF-C                       1

```

В `ahu17.csv` колонка `param` заполнена именами объектов. Замените их на имена параметров шаблона, лишние строки удалите и импортируйте: `node tools/importTags.js ahu17.csv --out data/config/instances/ahu17.json`, затем `node tools/checkModel.js`.

**Проверка привязок установки** — каждая точка: объект, имя на N30, сырое значение, значение параметра, флаги:

```bash

```

## Что проверить на N30 (пилот, этап 3а)

1. Отвечает ли N30 на Who-Is в сети объекта, какой `maxApduLengthAccepted` и поддерживает ли сегментацию.
2. Сколько объектов N30 отдаёт в одном ReadPropertyMultiple и что отвечает на слишком большой запрос (abort или ошибка).
3. Для каких типов объектов принимается SubscribeCOV, сколько подписок держит N30 (80 установок × ~20 объектов), какой `covIncrement` у аналоговых объектов.
4. Что N30 отвечает на неизвестный объект внутри RPM: ошибка по свойству или на весь запрос.
5. Запись с приоритетом 8 и снятие `NULL`: возвращается ли управление программе N30; какие приоритеты уже заняты программой.
6. Как N30 сообщает о неисправности датчика: `statusFlags.fault`, `reliability` или значение-заглушка.
7. Номера состояний multiState на N30 и их соответствие шаблону (`offset`).

Итог пилота — записка и, при необходимости, настройки по умолчанию для N30 (`BACNET_MAX_OBJECTS`, `BACNET_COV`).

## Ограничения

- Только BACnet/IP в одной IP-сети или с маршрутизацией IP. BBMD, регистрация внешнего устройства (foreign device) и устройства за маршрутизаторами BACnet (MS/TP, адрес `сеть:MAC`) не поддерживаются — на объекте N30 подключены к сети IP напрямую.
- Без ReadPropertyMultiple устройство не опрашивается (N30 его поддерживает).
- Сервер не отвечает на Who-Is и не виден как устройство BACnet: для чтения, записи и COV это не нужно.

## Нагрузка

Проверено на эмуляторе: 80 устройств, 1 600 тегов, все объекты на COV, значения меняются раз в секунду — около 3% одного ядра и 100 МБ памяти. Все теги в `good` через 0,5 с после запуска, все подписки оформлены через 1,5 с, снятие 1 600 подписок при остановке — 0,3 с.
